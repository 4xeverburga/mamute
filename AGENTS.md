# AGENTS — running Mamute here

Mamute is a Stack Overflow-style Q&A application. Stack: VRaptor 4 + Weld
CDI + Hibernate + JSP, Java 7 source/target, embedded Jetty 8 via
`br.com.caelum.vraptor.server.Main`.

The toolchain is installed already: `JAVA_HOME` is JDK 8 (Java 7
source/target does not compile on JDK 9+), and `mvn`, `node`, `npm` and
`mysql` are on the path.

---

## 1. Build

```bash
mvn -B -q compile
```

Classes go to `src/main/webapp/WEB-INF/classes/` (set in `pom.xml`); that
is the directory the app serves from. `-o` skips the network once the
dependencies are in `~/.m2`.

## 2. The database

MySQL 5.7 on `db:3306`, user `root`, empty password, database
`mamute_development`. Hibernate creates the schema on first boot.

`src/main/resources/development/hibernate.cfg.xml` hardcodes
`jdbc:mysql://localhost/...`, so pass the real URL in the environment —
`MamuteDatabaseConfiguration` reads `JDBC_URL`, `USER` and `PASSWORD` and
overrides the file:

```bash
JDBC_URL='jdbc:mysql://db:3306/mamute_development?autoReconnect=true&useUnicode=true&createDatabaseIfNotExist=true&characterEncoding=utf-8' \
USER=root PASSWORD='' \
mvn -B exec:java -Dexec.mainClass=br.com.caelum.vraptor.server.Main \
  -Dexec.args="not-grunt" -Dserver.port=8088
```

## 3. The config the app reads

VRaptor's `MamuteEnvironment` loads `/environment.properties` plus
`/<env>.properties`, falling back to `/mamute.properties`. The `host`
property builds absolute redirect and callback URLs, so it must match the
address you serve on. `development.properties` is gitignored; copy the
template and set the port:

```bash
printf 'host = http://localhost:8088\nforce.quartz.jobs = true\n' \
  > src/main/resources/development.properties
```

## 4. The seeded account

On a fresh database `DefaultAdminCreator` creates
`moderator@mamuteqa.org` and logs the generated password once, at startup:

```bash
grep -A3 'New admin user created' /tmp/mamute.log
```

Read the password from there rather than guessing.

## 5. Static assets

Only the LESS/JS sources are tracked; the CSS, the fonts and the images
are generated. `grunt less` regenerates the CSS, `grunt copy:ignored`
re-copies the unhashed dependencies into `css/deps` and `font`.

```bash
npm install
./node_modules/grunt-cli/bin/grunt less
./node_modules/grunt-cli/bin/grunt copy:ignored
```

Do **not** run `grunt build`: besides the CSS it deletes
`src/main/webapp/assets/`, rewrites `header.tag`, `coda.jspf`,
`showQuestion.jsp` and `terms.jspf` to hashed references, and renames
dependencies — hundreds of unrelated changes in the working tree.

## 6. Quirks worth knowing

- VRaptor registers a catch-all `/*` OPTIONS route, so a path with no
  route answers `405`, never `404`. A stray 405 usually means a missing
  static file; `/css/deps/custom.css` is referenced by the templates and
  generated by nothing.
- Build outputs (`src/main/webapp/WEB-INF/classes/`, `target/`) and
  `development.properties` are gitignored: a change there does not
  survive a fresh clone, so it is not part of the code.
- `mvn test` runs the unit tests; there is no browser automation and no
  seed data beyond the admin account above.
